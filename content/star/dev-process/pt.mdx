## Situação

Até fevereiro de 2026, as tarefas da LíderHub ficavam soltas no Notion: mais de 2 mil cards, cerca de 40% sem prioridade, 60% sem dizer se eram bug ou feature e quase nenhum ligado ao código. Ideia de feature virava um checkbox jogado numa página. Issues e PRs não seguiam padrão, e o time não tinha noção do que fazer primeiro.

## Tarefa

Éramos 3 devs e o CTO. Assumi organizar o fluxo de trabalho, do que entra no backlog até o que vai para produção.

## Ação

1. Levei a gestão de tarefas para o GitHub Projects, com o fluxo Backlog → In Dev → Testing → QA → Code Review → Done. Passei a escrever a maioria das issues e a distribuí-las entre os devs.
2. Criei templates de issue para bug, feature e tech debt, com prioridade e esforço, e documentei o fluxo num guia para o time.
3. Criei skills de IA para criar issues e PRs já no formato padrão, para ninguém depender de lembrar a regra.
4. Liguei o QA e os bloqueios ao Slack: quando uma task fica pronta para teste ou trava, o canal é avisado.
5. Conduzi a daily e planejei com o CTO cada fix e feature, por menor que fosse. Decidi o que entrava em cada deploy e garanti a entrega.

## Resultado

Até janeiro de 2026, nenhum merge vinha de uma branch ligada a uma issue. De fevereiro a outubro foram cerca de 100. Os incidentes no formato padrão foram de 0% para cerca de 90% em cinco meses, e conduzi mais de 100 deploys no período.
